# Biblioteca de componentes visuais

Organiza um conjunto reutilizável de componentes de interface com variantes, estados, tokens e regras de uso. Use quando telas repetem botões, campos e cards com diferenças sem motivo ou quando o produto precisa de uma base comum.

## Antes de começar

Reúna, a partir do pedido e do arquivo de instruções do projeto (se houver):

- Capturas, arquivos de design ou código das telas atuais.
- Cores, fontes e medidas já definidas para a marca.
- Tecnologia de implementação e bibliotecas de interface em uso.
- Plataformas atendidas e formas de interação (toque, mouse, teclado).

Se faltar algo decisivo, pergunte só o necessário. Se der para avançar, marque a lacuna e siga sem inventar dado.

## Passo a passo

1. Percorra as telas e agrupe elementos que cumprem a mesma função, anotando as variações encontradas e quais delas são acidentais.
2. Decida quais componentes entram na biblioteca e dê a cada um um nome pela função, não pela aparência.
3. Para cada componente, liste variantes e estados (padrão, foco, pressionado, desabilitado, carregando, erro) que fazem sentido no produto.
4. Defina tokens semânticos de cor, espaçamento, raio e tipografia e indique qual token cada parte do componente consome.
5. Escreva quando usar, quando evitar e como combinar cada componente, incluindo navegação por teclado, rótulo acessível e comportamento com texto longo.

## O que entregar

Inventário de componentes com anatomia, variantes, estados, tokens associados e orientações de uso.

## Conferência antes de entregar

- [ ] Não sobram dois componentes diferentes resolvendo a mesma tarefa sem justificativa.
- [ ] Todos os elementos interativos têm foco visível e estado desabilitado descritos.
- [ ] Nenhum valor solto de cor ou medida aparece onde deveria haver um token.

## Limites

Só diga que publicou, enviou, testou ou alterou algo se isso aconteceu. Peça aprovação antes de ação externa, com custo ou que não dê para desfazer.
