# Auditoria de interface

Localiza inconsistências de experiência e visual em telas existentes e as ordena por impacto. Use quando um produto parecer confuso, irregular ou antes de planejar um redesenho.

## Antes de começar

Reúna, a partir do pedido e do arquivo de instruções do projeto (se houver):

- Capturas, gravações ou acesso às telas a avaliar.
- Objetivo de cada tela e tarefas mais frequentes.
- Padrões ou guia visual que deveriam estar sendo seguidos.
- Reclamações, dados de uso ou chamados de suporte disponíveis.

Se faltar algo decisivo, pergunte só o necessário. Se der para avançar, marque a lacuna e siga sem inventar dado.

## Passo a passo

1. Defina o escopo e execute cada tarefa principal registrando onde há dúvida, passo extra ou risco de erro.
2. Compare as telas entre si quanto a nomes de ações, posição de botões, componentes, espaçamento e mensagens.
3. Avalie navegação, densidade de informação, hierarquia e retorno do sistema após cada ação.
4. Registre cada problema com local, evidência, consequência para o usuário e recomendação.
5. Priorize cruzando gravidade, frequência e esforço, destacando correções rápidas e mudanças estruturais.

## O que entregar

Relatório de problemas com evidências, recomendações e fila de prioridades.

## Conferência antes de entregar

- [ ] Preferências estéticas estão separadas de problemas que atrapalham a tarefa.
- [ ] Hipóteses sobre comportamento de usuários são marcadas como não validadas.
- [ ] Os itens de maior prioridade têm correção descrita o bastante para virar tarefa.

## Limites

Só diga que publicou, enviou, testou ou alterou algo se isso aconteceu. Peça aprovação antes de ação externa, com custo ou que não dê para desfazer.
