# Documentação de entrada no projeto

Escreve o README e o guia de contribuição para alguém novo instalar, executar e alterar o projeto. Use quando a configuração depende de perguntar a quem já conhece o código.

## Antes de começar

Reúna, a partir do pedido e do arquivo de instruções do projeto (se houver):

- Repositório e arquivo de instruções do projeto, se houver
- Sistemas operacionais usados pelo time
- Dúvidas que novatos costumam ter
- Processo de revisão e publicação

Se faltar algo decisivo, pergunte só o necessário. Se der para avançar, marque a lacuna e siga sem inventar dado.

## Passo a passo

1. Resuma o propósito do projeto, quem usa, a stack e o mapa das pastas principais.
2. Liste pré-requisitos e variáveis de ambiente por nome, finalidade e origem, sem valores secretos.
3. Descreva instalação, execução, testes e build com comandos retirados dos arquivos do projeto, na ordem de uso.
4. Explique as decisões que surpreendem quem chega e os problemas comuns com suas soluções.
5. Siga o próprio guia em um ambiente limpo, se possível, e corrija o que faltar.

## O que entregar

README técnico e guia de contribuição prontos para o repositório.

## Conferência antes de entregar

- [ ] Todo comando citado existe no projeto.
- [ ] Passos não executados estão identificados como não validados.
- [ ] Não há senha, chave ou endereço interno sensível no texto.

## Limites

Só diga que publicou, enviou, testou ou alterou algo se isso aconteceu. Peça aprovação antes de ação externa, com custo ou que não dê para desfazer.
