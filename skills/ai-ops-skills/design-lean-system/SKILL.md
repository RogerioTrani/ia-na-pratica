# Design system enxuto

Consolida tokens, tipografia, componentes e regras de composição em um guia curto e aplicável. Use quando um projeto pequeno ou em crescimento precisar de consistência sem manter uma documentação extensa.

## Antes de começar

Reúna, a partir do pedido e do arquivo de instruções do projeto (se houver):

- Telas e estilos atuais, no design ou no código.
- Identidade de marca aprovada.
- Componentes mais usados e próximas telas planejadas.
- Quem vai manter o guia e onde ele ficará.

Se faltar algo decisivo, pergunte só o necessário. Se der para avançar, marque a lacuna e siga sem inventar dado.

## Passo a passo

1. Recolha cores, fontes, medidas e componentes em uso e escolha uma versão oficial para cada duplicidade.
2. Declare tokens em dois níveis, valores base e papéis semânticos, no formato que o projeto já utiliza.
3. Documente somente os componentes necessários para as telas atuais e próximas, com estados e variantes.
4. Escreva regras de composição para grid, espaçamento, hierarquia e ações principais, ilustradas por uma tela montada.
5. Registre exceções aceitas, como propor mudanças e a ordem para migrar o que está fora do padrão.

## O que entregar

Guia compacto com tokens, tipografia, componentes, padrões de composição, exceções e plano de adoção.

## Conferência antes de entregar

- [ ] Uma tela comum pode ser montada sem inventar valores novos.
- [ ] Os nomes dos tokens e componentes batem entre guia e código ou a divergência está anotada.
- [ ] Não há itens documentados que o projeto não vá usar.

## Limites

Só diga que publicou, enviou, testou ou alterou algo se isso aconteceu. Peça aprovação antes de ação externa, com custo ou que não dê para desfazer.
